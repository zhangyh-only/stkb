# 技术基线

## 1. 目标

项目要支持“方案能够被代码验证，数据能够真实落地，过程和结果能够在 Web 端看见”。它不是完整业务系统的初版。

## 2. 数据职责

### PostgreSQL

保存知识对象和修订登记、业务实体、引用关系、验证运行及一致性状态，是结构化业务事实源。

### 正式知识文件

以 Markdown 验证 Agent 可直接阅读的知识形态。文件必须携带知识对象 ID、修订和来源信息，并能与 PostgreSQL 登记对账。

### pgvector

保存从正式知识内容派生的检索单元和 embedding。它用于召回，不定义知识对象身份。

### Neo4j

保存从正式对象和关系派生的图投影。它用于路径查询和关系扩展，不充当唯一事实源。

## 3. 可视化要求

Vue 工作台不是完整管理后台。每个能力页面应优先显示：

- 输入样例与本次假设；
- Python 处理阶段及状态；
- PostgreSQL 中的对象登记；
- 正式知识 Markdown 内容；
- pgvector 检索单元与命中结果；
- Neo4j 节点、关系与查询结果；
- 三种形态的一致性检查及错误。

## 4. 当前只搭底座

本轮只提供 FastAPI/Vue 启动骨架、本地 PostgreSQL/pgvector 和 Neo4j 环境、配置入口与工程检查。业务表、图约束和具体能力 API 必须在首个方案切片中通过真实样例反推。
